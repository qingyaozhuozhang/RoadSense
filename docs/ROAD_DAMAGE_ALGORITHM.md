# RoadSense 道路损伤识别与自动归档算法

本文根据 `houduan/core.py`、`houduan/obb_inference.py`、`houduan/location_state.py`、`qianduan/server/app.py` 和 `qianduan/server/record_naming.py` 的实现说明现阶段工作机制，参数以这些源文件为准。这里的等级是**工程内启发式分类**，不是经过标定的道路病害行业评估标准。

## 1. 采集、预处理与 YOLO-OBB

摄像头独立采集最新帧。YOLO 读取 `best.onnx`，按输入尺寸缩放并 Letterbox 填充（灰度值 114），从 BGR 转换为 RGB，转成 `float32` 的 NCHW 张量并归一化到 `[0,1]`。

模型输出由 `decode_predictions()` 解析：

1. 对类别得分取最大类别，低于置信度阈值 **0.30** 的候选被过滤。
2. OBB 模型提取旋转角度与旋转框，映射回原摄像头坐标；使用 OpenCV `NMSBoxesRotated`（必要时回退普通 NMS），IoU 阈值为 **0.50**，去除同一位置的重叠候选。
3. 对保留检测框绘制旋转四边形，结果显示在实时画面。

模型推理与视频编码上传是不同链路。采集 25 FPS 并不代表 YOLO 检测 25 FPS，真实识别速度受模型、CPU/GPU/NPU 与 ONNX Runtime provider 的限制。

## 2. 损伤等级划分（当前启发式算法）

对已保留检测框计算面积和画面面积的比值：

```text
ratio = Σ(检测框面积) / (图像宽度 × 图像高度)
```

当前代码的等级阈值为：

| 条件 | severity | 页面等级 |
|---|---:|---|
| 没有有效检测框 | 0 | 无损伤 |
| 有检测框，ratio ≤ 0.02 | 1 | 轻微 |
| 0.02 < ratio ≤ 0.10 | 2 | 中度 |
| ratio > 0.10 | 3 | 严重 |

**注意**：代码对检测框面积直接求和。若检测框互相重叠，面积可能重复计算；ratio 用于内部粗略分级，不能解释为精确路面损伤面积。最终等级还受模型检测质量与相机视角影响。

## 3. 巡检条件及定位选择

边缘端通过云端 `/api/command` 获取运行状态与会话 `session_id`：

- `STOP` 或 `PAUSE`：仅显示/传视频，不自动归档。
- `RUNNING`：每次完成 YOLO 检测后生成候选事件，并立即绑定**检测当时**的有效经纬度和定位来源。

定位 `PositionManager` 分别缓存两路 WGS84 坐标：

- **硬件 GPS**：有效期 `HARDWARE_TTL=5 秒`。
- **关联 Android 手机定位**：有效期 `PHONE_TTL=30 秒`。

选择策略：硬件 GPS 当前有效时使用硬件 GPS，否则使用当前设备所属手机的有效坐标；两路均无效则不生成归档事件。还必须保证坐标范围合法、有限且不为 `(0,0)`。

读取手机备用位置的边缘轮询线程使用 `/api/phone_location`，云端仅向当前经过认证的设备提供归属账号对应的实时位置；不能把其他用户的坐标错误归档到本设备。

归档线程还会在提交之前再次检查当前是否有有效定位。**没有位置时不保存空坐标记录**；之后定位恢复，也不会事后把已经错过的旧帧补成一条记录。

## 4. 时间与空间去重

识别事件携带 `seq`、`observed_at`、`session_id`、`severity`、经纬度与截图。归档线程按以下顺序筛选：

1. 只处理本次 `RUNNING` 会话的事件；已处理的 `(session_id, seq)` 不重复处理。
2. 舍弃超过 **4 秒**的旧识别事件。
3. 使用 Haversine 球面距离计算与本次会话已归档位置之间的距离：

```text
Δφ = φ2 − φ1
Δλ = λ2 − λ1
a = sin²(Δφ/2) + cos(φ1) × cos(φ2) × sin²(Δλ/2)
d = 2R × asin(sqrt(a)),  R = 6,371,000 m
```

4. 若在 **20 米**内已保存相同或更高等级记录，就跳过该事件；如果当前新等级更高，仍允许再次保存以反映等级变化。
5. 相邻上传尝试至少间隔约 **1 秒**，避免瞬时重复请求。
6. 上传 JPEG + 坐标等表单数据到云端 `/upload`；只有云端回复成功后才更新本次会话的“已保存地点”，失败不占用去重位置。

当前空间去重**只在一个巡检任务会话内有效**，进程重启或开始新会话后不会自动与历史 SQLite 记录跨日比较。20 米半径是项目的工程参数，不代表真实裂缝的精确空间边界；GPS 漂移可能引起漏记或重复。

## 5. 云端归档与账号来源

云端通过 `X-RoadSense-Device-ID`、`X-RoadSense-Token` 识别设备，将照片和记录与设备 `owner_id` 关联；记录包含时间、经纬度、等级、来源设备、位置来源、上传账号、巡检会话等字段。照片放在 `qianduan/data/images/`，数据库 `records.sqlite3` 保存元数据和文件名。

- **摄像头自动巡检**：归档名称为 `primary_<账号>_<YYYYMMDD_HHMMSS>_<唯一标识>`，有图片时保存 `.jpg`。
- **Android 手机辅助拍照**：先预览检测结果，不即时归档；点击确认后在满足权限和有效位置条件下保存，名称 `minor_<账号>_<YYYYMMDD_HHMMSS>_<唯一标识>`，并保存原图和标注图。
- `minor` / `primary` 表示**采集来源**，**不是**轻微/严重等级。

其中摄像头自动上传的账号由设备所属用户推导，业务字段会标记为设备代理上传，**不应被理解为该用户当时亲手操作了设备**。

## 6. 局限与建议

- 检测面积占比未做透视变换、重叠框面积并集、道路 ROI 标定或物理尺寸估计。
- 只根据空间距离与等级做启发式去重，没有跨时间的物体追踪、视觉相似度匹配或全局地理病害 ID。
- 模型推理 FPS 与视频传输 FPS 不同，CPU 推理可能明显低于视频帧率；需要优化模型、输入尺寸或可用硬件加速才可能进一步提高。
- 地理位置精度取决于传感器和设备归属，手机定位过期或硬件 GPS 漂移都会影响归档准确性。
- 若用于工程质量评估，建议先用人工标注数据校准阈值，评估漏检、误检、重复记录率，再研究轨迹关联及多帧稳定判别。
