# RoadSense 边缘计算节点技术与运行说明

边缘计算节点运行于树莓派或兼容的 Linux 计算设备，负责道路视频采集、YOLOv8-OBB 目标检测、双目立体测距、距离加权损伤评估、GNSS 定位及巡检结果上传。云端通过设备身份认证和任务状态控制，实现对边缘巡检流程的统一管理。

## 1. 硬件与运行环境

| 组成 | 说明 |
|---|---|
| 边缘计算主机 | Raspberry Pi 或兼容 Linux 主机，建议 Python 3.10+ |
| 图像传感器 | 支持左右拼接图像的双目摄像头；有效双目视频格式为 **1280×480** |
| 双目图像规格 | 左目 **640×480**，右目 **640×480** |
| 卫星定位 | **u-blox NEO-F10N 双频 GNSS 接收模块**，UART 接口 |
| AI 模型 | `best.onnx`，通过 ONNX Runtime 执行 YOLOv8-OBB 推理 |
| 网络 | 可访问云端 Flask HTTP API 的有线或无线网络 |

双目测距依赖 `camera_config.py` 中的标定参数；参数对应单目 640×480 的图像和指定摄像头组合。标定平移向量以毫米为单位，其基线长度约为 **120.33 mm**。更换物理相机或相机分辨率时，应使用与设备相匹配的标定参数，以保证空间测量具备几何依据。

## 2. 图像采集与视觉处理

### 2.1 摄像头采集

图像采集模块通过 OpenCV 获取视频帧，优先使用符合标定规格的双目数据。当存在有效双目帧时，系统将拼接画面拆分为左右目并完成立体校正：左目校正图像作为 YOLO 输入及视频展示基础，右目校正图像用于视差估计。

程序支持摄像头设备扫描、读取状态监测及设备重新接入。无法获得可用双目数据时，可使用符合输入要求的普通视频画面继续进行目标检测；未取得可靠双目距离的检测结果按未加权面积规则评估。

### 2.2 YOLOv8-OBB 道路损伤识别

系统利用 `best.onnx` 检测道路裂缝（Crack）和坑洞（Hole）。模型将采集图像经等比例缩放、Letterbox 填充、颜色通道变换和归一化处理后执行推理。当前模型输入尺寸为 **640×640**。

后处理根据类别分数筛选候选框，并采用旋转框 NMS 抑制重复目标。默认置信度阈值为 **0.30**，NMS IoU 阈值为 **0.50**。输出目标类别、置信度、旋转框四角点和检测框面积；旋转框坐标被还原到左目或当前视频帧坐标系。

### 2.3 双目距离估计

`stereo_distance.py` 使用 **StereoBM（块匹配）** 计算校正后左右目图像的视差，并结合标定矩阵 `Q` 将视差信息转换为三维空间坐标。系统根据 YOLO 旋转检测框生成目标区域掩码，在其中筛选有效视差与有效距离像素，经异常值筛选后计算目标距离估计值。

距离筛选区间由 `STEREO_MIN_DISTANCE_M` 与 `STEREO_MAX_DISTANCE_M` 控制，默认分别为 **0.25 m** 和 **12.0 m**。深度数据不足、无效或超出设定范围时，该检测目标的距离标记为不可用。距离估计结果受标定精度、图像纹理、环境光照和视差匹配质量影响。

### 2.4 距离加权损伤评估

系统分别统计检测框面积占比（`AREA`）与距离加权得分（`SCORE`），并以 **`SCORE`** 作为边缘端损伤等级判定依据。有效距离较近的目标具有较高权重，距离较远的目标权重较低；没有有效距离的目标采用权重 1。

| 距离范围 | 面积权重 |
|---|---:|
| 有效距离不大于 0.5 m | 1.50 |
| 0.5–2.0 m | 从 1.50 线性变化至 1.00 |
| 2.0–4.0 m | 从 1.00 线性变化至 0.75 |
| 不小于 4.0 m | 0.75 |
| 无有效距离 | 1.00 |

分级阈值为：无目标为无损伤；存在目标且 `SCORE ≤ 2%` 为轻微，`2% < SCORE ≤ 10%` 为中度，`SCORE > 10%` 为严重。该评分用于巡检场景的工程风险提示，不代表真实道路病害面积或法定损伤等级。

实时视频展示检测目标的旋转框与类别；在测距有效时显示相应目标距离，同时显示面积占比、加权得分、综合等级与测距状态。

## 3. GNSS 与移动端协同定位

边缘设备通过 UART 读取 NEO-F10N 的 NMEA RMC 定位报文，校验数据完整性与定位有效状态后生成 WGS84 经纬度。默认串口路径为 `/dev/serial0`，波特率为 `38400`，实际配置应与硬件一致。

串口接线遵循：GNSS TX → 树莓派 RX；GNSS RX → 树莓派 TX；GND → GND。通信电平必须满足树莓派 GPIO 的 **3.3V 兼容要求**，供电应遵循实际模块规格。

定位选择规则：

1. 在 **5 秒有效期**内存在可用硬件 GNSS 坐标时，优先使用硬件定位。
2. 硬件定位无效时，允许使用**与当前设备所属账号关联**的手机定位，手机定位有效期为 **30 秒**。
3. 两种来源均不可用时，仅提供检测展示，不执行自动归档。
4. 坐标必须满足经纬度范围及有效性检查，不接受无效数据或 `(0,0)` 占位坐标。

`GPS_UPLOAD_INTERVAL` 与 `PHONE_POLL_INTERVAL` 的默认值均为 **0.5 秒**，分别对应边缘端位置状态同步和手机备用位置轮询的目标间隔。GNSS 接收机与 Android 系统生成新定位结果的实际频率不由上述参数直接决定。

## 4. 巡检执行与归档条件

设备经身份认证从云端获取 `RUNNING`、`PAUSE`、`STOP` 等巡检状态。只有在运行中的有效会话内，边缘端才生成可归档的损伤检测事件。事件在识别发生时绑定有效坐标，上传前再次检查位置状态。

归档流程依次检查任务会话、事件时效、坐标有效性以及空间重复情况；同一巡检任务内，**20 米**范围内已保存相同或更高等级记录时，不再归档同类低优先级事件。如新检测等级更高，可生成新的记录。云端确认写入后，边缘端才更新去重状态。

归档图片及元数据由云端统一保存；边缘端可在本地保留部分中度或严重损伤图像用于运行记录。

## 5. 环境配置与启动

```bash
cd houduan
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements_runtime.txt
```

边缘运行配置由 `houduan/.env` 提供，主要字段如下：

| 字段 | 功能 |
|---|---|
| `CLOUD_BASE_URL` | 云端服务访问地址 |
| `DEVICE_ID`、`DEVICE_TOKEN` | 设备身份与认证令牌 |
| `CAMERA_INDEX`、`CAMERA_SCAN_INTERVAL` | 摄像头编号与设备扫描间隔 |
| `YOLO_MODEL` | ONNX 检测模型路径 |
| `GPS_PORT`、`GPS_BAUD` | GNSS 串口路径与波特率 |
| `GPS_UPLOAD_INTERVAL` | 设备定位状态上报间隔 |
| `PHONE_POLL_INTERVAL` | 手机备用位置查询间隔 |
| `STEREO_MIN_DISTANCE_M`、`STEREO_MAX_DISTANCE_M` | 双目距离有效范围（可选） |
| `VIDEO_RENDER_FPS`、`VIDEO_UPLOAD_FPS` | 视频预览与上传目标帧率 |

管理员可从云端设备管理界面获取设备专属配置。`DEVICE_ID` 和 `DEVICE_TOKEN` 必须与云端登记信息一致。

在主程序未占用串口时，可单独验证 GNSS 数据解析：

```bash
python -m rpi.neo_f10n_simple --port /dev/serial0 --baud 38400
```

启动边缘巡检程序：

```bash
python core.py
```

云端完成设备登记和账号归属配置后，可在网页控制台选择相应设备执行巡检。

## 6. 运行状态与维护

- **摄像头状态**：检查设备节点、视频输出规格、图像采集与校正结果；双目测距须与标定规格一致。
- **模型推理**：根据 ONNX Runtime 可用执行后端配置 CPU 或硬件加速；采集 FPS、显示 FPS 与推理 FPS 应分别评估。
- **距离有效性**：目标纹理不足、遮挡或视差不可靠时，允许无深度评估，不以异常深度作为有效测量结果。
- **GNSS 状态**：核对串口权限、UART 参数、天线信号及 RMC 定位状态；卫星定位自身不依赖云端网络。
- **设备认证**：云端拒绝设备请求时，检查设备标识、令牌及账号归属配置。
- **部署安全**：设备令牌及定位信息属于受保护的部署数据，建议通过加密网络传输并妥善管理配置文件。

算法原理及分级公式详见 `../docs/ROAD_DAMAGE_ALGORITHM.md`。
